## 安装 Alauda Build of Jaeger v2


**前置条件**

- An OpenSearch 3.x instance is available, and you have the endpoint URL, username, and password for it.

**操作步骤**

1. 设置用于连接 OpenSearch 的环境变量：

    ```bash
    export OPENSEARCH_ENDPOINT='<OpenSearch endpoint URL>'
    export OPENSEARCH_USER='<OpenSearch username>'
    export OPENSEARCH_PASS='<OpenSearch password>'
    ```

2. 获取平台配置与 Jaeger 相关的容器镜像：

    ```bash
    # 删除 JAEGER_ES_ROLLOVER_IMAGE，新增 JAEGER_ES_INDEX_CLEANER_IMAGE
    export JAEGER_ES_INDEX_CLEANER_IMAGE=$(echo "$JAEGER_RELATED_IMAGES" \
      | jq -r '.[] | select(.name=="component.jaeger-es-index-cleaner") | .image')
    ```

4. 创建 Jaeger 命名空间与 OpenSearch 凭据 Secret：

    ```bash
    kubectl create namespace ${JAEGER_NS}

    kubectl create secret generic opensearch-credentials \
      --namespace=${JAEGER_NS} \
      --from-literal=OPENSEARCH_USER=${OPENSEARCH_USER} \
      --from-literal=OPENSEARCH_PASS=${OPENSEARCH_PASS}
    ```

    验证 Secret 创建结果：

    ```bash
    kubectl get secret opensearch-credentials -n ${JAEGER_NS}
    ```

使用 jaeger-es-index-cleaner 定期清理

:::info 为什么不使用 jaeger-es-rollover init
Jaeger 社区另一个工具 `jaeger-es-rollover` 的 `init` 子命令会调用 Elasticsearch 的 `_ilm/policy/...` 端点校验 ILM 策略是否存在，而 OpenSearch 使用的是 `_plugins/_ism/policies/...`，两者不兼容，`init` 会直接失败（参见 [jaegertracing/jaeger#7121](https://github.com/jaegertracing/jaeger/issues/7121)）。

本文档使用的是 **按日索引 + `jaeger-es-index-cleaner`** 组合，**不依赖** rollover alias，也就无需调用 `jaeger-es-rollover init`。
:::

**工作原理**

Jaeger v2 的 OpenSearch 后端默认生成类似 `acp-<cluster>-jaeger-span-2026-04-22` 的索引，`jaeger-es-index-cleaner` 会匹配 `<prefix>-jaeger-(span|service|dependencies|sampling)-YYYY-MM-DD` 的索引，比较日期后缀与"今天减去 N 天"，删除超期索引。


**操作步骤**

1. 设置 index-cleaner 相关的环境变量：

    ```bash
    # 索引保留天数：超过该天数的索引将被删除
    export JAEGER_INDEX_RETENTION_DAYS="7"
    # 每日执行时刻（UTC）。示例 "30 2 * * *" 表示 UTC 02:30（北京时间 10:30）
    export JAEGER_CLEANER_SCHEDULE="30 2 * * *"
    ```

    :::info
    **索引保留参数与 Jaeger 的关系**

    为避免 Jaeger UI 查询到刚被 cleaner 删除的索引，建议：`JAEGER_INDEX_RETENTION_DAYS`（cleaner 保留天数）与 Jaeger 的 `max_span_age` 保持一致，例如均设为 7 天。
    :::

2. 创建 `jaeger-index-cleaner.yaml`，以 `CronJob` 形式部署 index-cleaner：

    ```yaml title="jaeger-index-cleaner.yaml"
    apiVersion: batch/v1
    kind: CronJob
    metadata:
      name: jaeger-es-index-cleaner
      namespace: ${JAEGER_NS}
    spec:
      schedule: "${JAEGER_CLEANER_SCHEDULE}" # [!code callout]
      concurrencyPolicy: Forbid # [!code callout]
      successfulJobsHistoryLimit: 3
      failedJobsHistoryLimit: 3
      jobTemplate:
        spec:
          backoffLimit: 3
          template:
            spec:
              restartPolicy: Never
              containers:
                - name: jaeger-es-index-cleaner
                  image: "${JAEGER_ES_INDEX_CLEANER_IMAGE}"
                  args: # [!code callout]
                    - "${JAEGER_INDEX_RETENTION_DAYS}"
                    - "${OPENSEARCH_ENDPOINT}"
                  env:
                    - name: INDEX_PREFIX # [!code callout]
                      value: "${JAEGER_ES_INDEX_PREFIX}"
                    - name: INDEX_DATE_SEPARATOR
                      value: "-"
                    - name: ES_TLS_ENABLED
                      value: "true"
                    - name: ES_TLS_SKIP_HOST_VERIFY # [!code callout]
                      value: "true"
                    - name: ES_USERNAME
                      valueFrom:
                        secretKeyRef:
                          name: opensearch-credentials
                          key: OPENSEARCH_USER
                    - name: ES_PASSWORD
                      valueFrom:
                        secretKeyRef:
                          name: opensearch-credentials
                          key: OPENSEARCH_PASS
                  resources:
                    requests:
                      cpu: 50m
                      memory: 64Mi
                    limits:
                      cpu: 500m
                      memory: 256Mi
    ```

    <Callouts>
      1. `schedule` 采用标准 Cron 表达式（UTC 时区）。建议安排在集群低峰期执行，每日一次足矣。
      2. `concurrencyPolicy: Forbid` 确保上一次清理未完成时不会启动新 Job，避免并发删除造成 OpenSearch 的短时压力。
      3. `args` 是 `jaeger-es-index-cleaner` 的位置参数：第一个为**保留天数**，第二个为 OpenSearch 端点。注意这里不传 `ROLLOVER=true`，以使用默认的"按日索引"匹配模式。
      4. `INDEX_PREFIX` 必须与 Jaeger `indices.index_prefix` 完全一致（本文为 `acp-<cluster>`），否则 cleaner 找不到对应索引。
      5. `ES_TLS_SKIP_HOST_VERIFY=true` 对应 Jaeger 端 `insecure_skip_verify: true` 的 TLS 策略；若已按 [使用自签名 CA 严格校验 OpenSearch 证书](#tls-advanced) 加固，请改为挂载 CA 并设置 `ES_TLS_CA_FILE`。
    </Callouts>

4. 渲染并部署 CronJob：

    ```bash
    envsubst < jaeger-index-cleaner.yaml | kubectl apply -f -
    ```
